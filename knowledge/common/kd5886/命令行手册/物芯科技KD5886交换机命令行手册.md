## 命令行格式约定

| 格式 | 意义 |
| --- | --- |
| 粗体 | 命令行关键字（命令中保持不变、必须照输的部分）采用加粗字体表示。 |
| 斜体 | 命令行参数（命令中必须由实际值进行替代的部分）采用斜体表示。 |
| [] | 表示用“[ ]”括起来的部分在命令配置时是可选的 |
| { x | y | ... } | 表示从多个选项中仅选取一个。 |
| [ x | y | ... ] | 表示从多个选项中选取一个或者不选。 |
| { x | y | ... } * | 表示从多个选项中至少选取一个。 |
| [ x | y | ... ] * | 表示从多个选项中选取一个、多个或者不选。 |
| &<1-n> | 表示符号&前面的参数可以重复输入1～n次。 |
| # | 由“#”号开始的行表示为注释行。 |
| RANGES | 表示一个范围，由使用者输入，支持x-y/x,y,z/x-y,z/x,y-z/x五种输入方式。注意输入时逗号后不要有空格。 |

## 命令行简介

在交换机上运行应用程序后即会进入命令行模式，使用’?’可以查看当前视图可以输入的命令，支持命令补齐、自动匹配。

支持的视图如下：

| 视图 | 说明 |
| --- | --- |
| 顶层视图 | 从顶层视图可以进入其它视图。从非顶层视图切换到另一个非顶层视图必须通过切换到顶层视图才能进入。退出某个视图时使用exit命令且必须输入完整的‘exit’四个字符,不可输入部分字符。 |
| interface | 分为单端口视图和端口范围视图，单端口视图能更改单个端口的配置，端口范围视图下的更改对整个端口范围均生效。 |
| vlan | 从vlan视图能进入单vlan视图，在单vlan视图下管理单个vlan。 |
| lag | 管理聚合口 |

| l3 | 管理路由 |
| multicast | 二层组播和三层组播相关配置均在此视图下 |

| qos | 配置全局的qos映射表、shaper模板等。 |
| mpls | 管理mpls的静态表项。 |
| mirror | 镜像相关的功能在此视图。 |
| nat | 配置网络地址转换的转换规则等。 |

### save

save命令用来保存当前配置信息到文件中。文件存储位置为：与执行交换机管理软件同一目录下的start_conf.conf文件。

交换机管理软件在启动时会去读取同一目录下的start_conf.conf文件实现配置恢复。

### gencfg

gencfg命令用来开始生成单片机模式使用的配置文件。执行完gencfg后，使用者可以继续执行其它配置命令，在执行savecfg命令前的所有寄存器写相关操作都会被记录到单片机模式配置文件中。

单片机模式配置文件存储位置为：与执行交换机管理软件同一目录下的switch_cfg_simplified文件。

### savecfg

savecfg命令用来结束生成单片机模式使用的配置文件。执行完savecfg后，不会有新的配置信息新增到单片机模式使用的配置文件中。

### egress

格式：egress service-tag HHHH

参数说明：用户自定义出方向TPID

HHHH：十六进制数，指定自定义TPID，默认为88a8

配置此功能后，从该端口转出的tag报文的TPID会是用户自定义值。

实例：

KD-CLI(Interface 0)# egress service-tag 1234（设置端口0出报文的TPID为1234）

flow-control

格式：[no] flow-control

参数说明：设置端口流控功能，缺省情况下端口关闭该功能。

flow-control：开启指定端口流量控制功能

no flow-control：关闭指定端口流量控制功能

配置flow-control命令后，设备具有发送和接收流量控制报文的能力：当本端发生拥塞时，设备会向对端发送流量控制报文；当本端收到对端的流量控制报文后，会停止报文发送。注意：本端对端均要开启此功能！

实例：

KD-CLI(Interface 2)# no flow-control（关闭端口2的流量控制功能）

frame-type

格式：frame-type {all|tagged|untagged-and-priority-tagged}

参数说明：设置端口接收报文类型，缺省情况下端口允许接收所有类型报文

all：端口接收所有类型的报文

tagged：端口仅接收tagged报文

untagged-and-priority-tagged：端口仅接收untagged报文或优先级tagged报文

配置此功能后，端口会选择过滤接收到的报文类型，发送报文不受影响。

实例：

KD-CLI(Interface 2)# frame-type tagged

（设置端口2仅接收tagged报文，其它报文默认丢弃）

frame-length

格式：frame-length set LEN

参数说明：设置端口接收报文的最大帧长，缺省情况下为9600字节

LEN：最大帧长，范围：1518-12072字节

配置此功能后，端口会过滤丢弃超过该帧长的报文。

实例：

KD-CLI(Interface 2)# frame-length set 1518（设置端口2接收报文的最大帧长为1518）

ingress-filter

格式：[no] ingress-filter

参数说明：设置端口入方向VLAN检查，缺省情况下端口开启入方向VLAN检查

ingress-filter：设置指定端口开启入方向VLAN检查

no ingress-filter：设置指定端口关闭入方向VLAN检查

配置ingress-filter命令后，被配置端口会检查报文所属VLAN是否允许该端口转发，允许则转发，不允许则丢弃。

实例：

KD-CLI(Interface 2)# no ingress-filter（设置端口2不开启入方向VLAN检查）

interface

格式：interface [<0-55>|RANGES]

参数说明：切换端口视图

<0-55>：切换为指定端口的视图，范围不同设备会有所不同，以实际设备为准。

RANGES：切换为多个端口的视图，格式：n1-n2或n1,n3

<cr>：切换为所有端口的视图

实例：

KD-CLI# interface 7-8（切换为端口7-8的视图）

KD-CLI# interface 7,9（切换为端口7,9的视图）

loopback

格式：loopback {pcs-internal|pcs-external|phy-internal|phy-external}

no loopback

参数说明：设置端口环回，缺省情况下端口关闭该功能

pcs-internal：设置端口为PCS内环

pcs-external：设置端口为PCS外环

phy-internal：设置端口为PHY内环

phy-external：设置端口为PHY外环

no loopback：关闭端口环回

在进行某些特殊功能测试时，例如初步定位以太网故障时，需要开启以太网端口环回测试功能。

实例：

KD-CLI(Interface 2)# loopback phy-internal（设置端口2环回为PHY内环）

mac-address

格式：mac-address source-unknown [learn|discard|cpu]*

no mac-address source-unknown

参数说明：配置端口MAC学习模式，缺省情况下端口自动学习MAC不丢弃不拷贝到CPU

learn：源未知报文自动学习MAC地址

discard：源未知报文丢弃

cpu：源未知报文拷贝到CPU

<cr>：源未知报文不自动学习MAC、不丢弃、不拷贝到CPU

no mac-address source-unknown：配置恢复默认值（自动学习MAC不丢弃不拷贝到CPU）

实例：

KD-CLI(Interface 2)# mac-address source-unknown cpu discard learn

（端口2自动学习MAC，源未知报文丢弃，且拷贝到CPU）

max-limit

格式：max-limit NUM

no max-limit

参数说明：设置端口MAC学习最大个数，缺省情况下端口默认没有个数限制

max-limit NUM：设置端口MAC学习个数为指定值，不同芯片范围不同

no max-limit：恢复端口MAC学习最大个数为默认值（没有限制）

实例：

KD-CLI(Interface 2)# max-limit 321（设置端口2的MAC学习最大个数为321个）

mstp

格式：mstp instance <0-63> state {forwarding|learning|discarding}

参数说明：设置端口的MSTP实例与报文处理方式，缺省情况下端口默认仅实例0转发报文

forwarding：报文转发且MAC地址学习

learning：报文不转发且MAC地址学习

discarding：报文不转发且MAC地址不学习

此功能设置的报文转发学习状态要与mac-address命令中的设置保持一致，两者有一处设置不转发，报文则不转发。

实例：

KD-CLI(Interface 2)# mstp instance 44 state forwarding

（端口2报文在实例44中转发，且MAC地址学习）

port-isolate

格式：port-isolate

no port-isolate

参数说明：设置端口隔离，缺省情况下默认无端口隔离

port-isolate：将指定端口加入隔离

no port-isolate：将指定端口移出隔离

配置port-isolate命令后，加入隔离的端口之间无法进行二层通信。

实例：

KD-CLI(Interface 2)# no port-isolate（将端口2移出隔离）

qinq

格式：qinq {enable|disable}

参数说明：qinq enable : 设置port-type为s-custom

qinq disable ：设置port-type为c

实例：

KD-CLI(Interface 2)# qinq enable（设置端口2为qinq使能）

### qos

#### qos cos

格式：qos cos <0-7>

no qos cos

参数说明：

cos <0-7> ：设置端口默认cos值。

no ：将端口默认cos恢复成0。

示例：

KD-CLI(Interface 47)# qos cos 2（设置端口47的默认cos值为2）

描述：

端口默认cos值是0，此命令用于改变端口cos值。

进入端口的报文按以下流程决定入哪个队列。

#### qos trust

格式：

[no] qos trust { cos | dscp }

参数说明：

cos ：信任报文tag内的pri值。

dscp : 信任IPv4/IPv6报文的DSCP值。

no : 删除信任类型

示例：

在端口47上使能IP报文按DSCP映射表入队列。

KD-CLI(Interface 47)# qos trust dscp

描述：

qos trust cos 和 qos trust dscp可以同时配置在一个端口上，按标签‘qos cos’内的流程决定报文进入哪个队列。

#### qos map

格式：

qos map cos-queue cos {RANGES|<cos_value>} queue <queue_value>

no qos map cos-queue cos {RANGES|<cos_value>}

参数说明：

cos-queue：设置cos到queue的映射关系。

cos {RANGES|<cos_value>}：待映射的cos值，范围0-7，支持x-y/x,y,z/x-y,z/x,y-z/x五种输入方式。注意输入时逗号后不要有空格。

queue <queue_value>：映射到的queue值，范围0-7。

no：将指定的cos到queue的映射关系恢复为默认值，默认为cos 0-7对应映射到queue 0-7。

示例：

在端口0上设置cos值2和4映射到队列5。

KD-CLI(Interface 0)# qos map cos-queue cos 2,4 queue 5

描述：

仅设置映射关系不能改变报文入队值，需结合qos trust及报文类型判断报文进入哪个队列，详细流程参见标签‘qos cos’内的流程图。

#### qos shaper/queue-shaper

格式：

qos {shaper| queue-shaper queue {RANGES|< queue_value >} } template <shaper_template_id>

no qos {shaper| queue-shaper queue {RANGES|< queue_value >} }

参数说明：

shaper: 端口下行对报文shaper。

queue-shaper queue {RANGES|< queue_value >}  ：端口下行对某个队列的报文shaper。queue_value范围0-7。

template <shaper_template_id> ：指定shaper模板id（id范围0-31）。shaper模板在QOS视图下配置。

no : 删除端口/队列下行shaper限速。

示例：

限制端口47下行队列2的速率为2Mbps。

step1: 在QOS视图下创建shaper模板，使用shaper模板id 8。

KD-CLI(Qos)# qos shaper-template 8 cir 2000 cbs 40000

step2:在端口47上设置qos queue-shaper

KD-CLI(Interface 47)# qos queue-shaper queue 2 template 8

#### qos schedule

格式：

qos schedule <weight_queue0> <weight_queue1> <weight_queue2> <weight_queue3> <weight_queue4> <weight_queue5> <weight_queue6> <weight_queue7>

no qos schedule

参数说明：

schedule ：设置出队列调度方式

<weight_queueX> : 指定每个队列的调度方式，‘0’ 表示SP调度，非零值表示DWRR调度的权值。

no qos schedule : 恢复出队列调度方式为默认值，即队列0—5为DWRR，权值均为1，队列6和队列7为SP。

示例：

配置端口47的出队列调度方式为队列0到队列4为DWRR，权值分别为10、20、30、40，队列5到队列7为SP

KD-CLI(Interface 47)# qos schedule 10 20 30 40 0 0 0 0

#### qos dscp-mutation

格式：

[no] qos dscp-mutation

参数说明：

## acl视图

| 命令 | 简要介绍 |
| --- | --- |
| create | 创建一条ACL或udf表项。 |
| destroy | 删除一条ACL或udf表项。 |
| install | 某条ACL已配置且需要生效时，执行此命令，以用来配置生效。 |
| uninstall | 某条已install的ACL暂时不需要生效时，执行此命令，以用来配置失效。 |
| reinstall | 某条已install的ACL经过配置修改且需要生效时，执行此命令，以用来新的配置生效。 |
| add | 为指定ACL添加规则、动作、优先级。 |
| del | 删除指定ACL已配置的指定规则、动作。 |
| car-action | 指定对限速数据包采取的动作，包括：丢弃和通过。 |
| policer-template | 创建限速模板（规则），对符合规则的数据包进行过滤。 |
| no | 删除所创建的car-action或policer-template |
| set | 设置ACL优先级排列模式（增序/降序）。 |
| clear | 清除已生效ACL的命中统计计数。 |
| show | 显示ACL的配置信息、状态信息或限速相关配置信息。 |
| exit | 退出ACL视图，返回上一级视图。 |

配置简介：

使用create命令创建一条ACL。

使用add命令为当前ACL添加规则（先指定ACL类型、再添加规则）、动作、优先级（可选）。

通过del命令删除已存在的指定配置，可重新配置。

使用install命令使当前ACL生效。（对于已生效的ACL修改后，使用reinstall重新生效）。

当不再需要当前ACL时，使用uninstall命令使ACL失效后才可以使用destroy命令删除此条ACL。

前提说明：以下命令行涉及到的参数格式如下：

ID ：十进制数值

HH ：十六进制数值

A.B.C.D ：点分十进制数值

前提说明：以下命令行涉及到的掩码说明如下：

HH 和 A.B.C.D ：换算成二进制后，“1” 表示 “匹配” ，“0” 表示 “不关心” 。

例如：	物理端口=0、掩码=FE 表示当前ACL规则可以匹配到来自端口0和端口1的报文。

IP=192.168.1.1、掩码=255.255.255.0 表示当前ACL规则可以匹配到IP地址为192.168.1.0 ~ 192.168.1.255网段的报文。

### create命令

#### create group

命令格式：create group ID entry [ID]

使用说明：创建一条指定编号或自动分配编号的ACL。缺省情况下，不存在任何 ACL。使用create命令时，如果指定编号的ACL 不存在，则创建该ACL，否则提示该编号的ACL已经存在。

group ID ：目前指定为0，不可更改。

entry [ID] ：指定ACL的编号，取值范围为0-2999。若未指定本参数，系统将会自动分配一个未创建过的最小编号。

使用举例：

create group 0 entry	创建一条ACL，编号由软件自动指定。

create group 0 entry 0	创建一条编号为0的ACL。

#### create udf-entry

命令格式：create udf-entry position VAL0 VAL1 VAL2 VAL3

使用说明：创建一条用于用户自定义匹配的表项，其中包含4个参数，均代表匹配位置下标，从0开始计数，计数起始位置均一致（报文的第一字节为位置下标0）。参数范围0-255。注：

在创建一条udf类型的ACL后，需要使用此命令创建一条udf-entry，然后执行add rule udf udf_entry_id ID group 0 entry ID。目前支持一条该表项，即：仅可执行一次该命令，否则提示失败，可通过删除旧表项，再创建新表项。

使用举例：

create udf-entry position 0 5 10 15	创建用户自定义匹配表项，匹配位置分别为下标0、下标5、下标10、下标15。

create udf-entry position 1 1 1 1		创建用户自定义匹配表项，匹配位置仅为下标1。

#### add action

命令格式：

add action{ flags | dscp_new ID | vlanprio_new ID | cos ID | dp ID | vlancfi_new ID | redirect_port ID | redirect_nexthop ID | redirect_isdx ID | mirror ID | policer car-action ID policer-template ID | rx_timestamp_enable <0-1> | tx_timestamp ID | copy_to_cpu_once <0-1> |copy_to_cpu <0-1> | cpu_queue ID | drop <0-1> | loopback <0-1> | no_maclearn <0-1> | force_l2 <0-1> | force_l3 <0-1> | no_route <0-1> | second_search_enable <0-1> }group ID entry ID

使用说明：为指定编号的ACL添加动作。

flags ：标志位，针对特殊情况处理。

dscp_new ID ：重写dscp。范围0~63。对于IP报文三层转发，配置该动作后需要进入相应的报文出端口执行qos dscp-mutation命令。对于IP报文二层转发，需要在三层报文操作步骤基础上，额外使能force_l3。注：dscp为ipv4中TOS字段的高6bit。

vlanprio_new ID ：重写vlan的优先级字段，ID范围0~7。

cos ID ：配置队列号。ID范围0~7。

dp ID ：配置丢弃等级。ID范围0~3。

vlancfi_new ID ：重写vlan的cfi字段，ID范围0~1。

redirect_port ID ：重定向到端口。ID范围0~19。对于IP报文三层转发需要与目的IP与之对应的路由存在！

redirect_nexthop ID ：重定向到下一跳。ID范围0~8191。对于报文本VLAN内转发，建议使用add action redirect_port命令。对于跨VLAN转发可使用本命令或add action redirect_port命令。注：对于IP报文三层转发需要与目的IP与之对应的路由存在！

redirect_isdx ID ：重定向到isdx。ID范围0~8191。

mirror ID ：用于配置镜像探针号，ID范围0~2；0/1/2分别对应三个镜像探针。在配置镜像探针时需要配置的被镜像端口号为报文如端口外的任意端口号，方向必须为RX。当没有配置此动作时，若一个报文命中多个镜像探针时（在不同流程中），最终只采用探针号最小的那个镜像探针。

policer car-action ID policer-template ID ：policer用于限速使用。car-action此前已创建，此处用于绑定具体ID，范围0~1023。policer-template此前已创建，此处用于绑定具体ID，范围0~31。注：此处car-action与policer-template的绑定要与car-action章节中的两者绑定要严格保持一致！

rx_timestamp_enable <0-1> ：转发至CPU报文接收时间戳打入使能。置1使能，清0不使能。相对于原始报文增加8 bytes（位于CRC前）。注：需要配合动作tx_timestamp结合使用。

tx_timestamp ID ：用于选择报文发出时报文ID以及时间戳的存储寄存器。 ID范围0~3。

copy_to_cpu_once <0-1> ：报文复制到CPU队列一次使能。置1使能，清0不使能。当多次命中时，仅会复制报文到CPU队列一次。可结合add action cpu_queue ID 命令指定队列号。

copy_to_cpu <0-1> ：报文复制到CPU队列使能。置1使能，清0不使能。可结合add action cpu_queue ID 命令指定队列号。

cpu_queue ID ：报文被复制到CPU时，用于指定CPU队列号，ID范围0~7。

drop <0-1> ：报文丢弃使能。置1使能，清0不使能。该字段在两次匹配中只要有一次结果为1，则报文就会被丢弃。注：force_l2或force_l3置1时，此动作不再生效。

loopback <0-1> ：报文环回转发使能（报文被转发至发送端口）。在进行环回转发时，报文不会被修改。置1使能，清0不使能。注：ACL的其它action配置不被影响！

no_maclearn <0-1> ：报文不进行mac学习学习使能。置1使能，清0不使能。

force_l2 <0-1> ：强制二层转发使能。置1使能，清0不使能。与force_l3互斥，不可同时置1。

force_l3 <0-1> ：强制三层转发使能。置1使能，清0不使能。与force_l2互斥，不可同时置1。

no_route <0-1> ：报文不进行路由使能。置1使能，清0不使能。对于报文三层转发而言，该动作置1，报文将不再走路由，而是丢弃。

second_search_enable <0-1> ：两次查找都命中时，若第二次动作表中此项置1，则只使用第二次的ACTION表。若未配置此动作且两次命中的ACTION都起作用时，两次查找冲突的动作以第一次为准。

使用举例：

add action redirect_port 0 group 0 entry 0	向编号为0的ACL添加端口重定向动作,命中ACL的报文将会在端口0发送出去。

add action copy_to_cpu 1 group 0 entry 0	向编号为0的ACL添加拷贝报文上送CPU动作，命中ACL的报文将在原有转发基础上，复制一份报文上送到CPU。

### policer-template

命令格式：policer-template <0-31> cir <0-10000000> cbs <0-10000000> pir <0-10000000> pbs <0-10000000> [(color-blindness (enable|disable [(coupling (enable|disable))]))]

使用说明：与car-action联合使用。

policer-template 表示限速模板，ID范围0-31。

cir：指定承诺信息速率（Committed information Rate），即保证能够通过的速率。cir必须小于pir。范围0-10000000，单位：kbps。

cbs：指定承诺突发尺寸（Committed Burst Size），即瞬间能够通过的承诺流量，即第一个令牌桶的深度（假定该桶C桶）。范围0-10000000，单位：bytes。

pir：指定峰值速率（Peak information Rate），即最大能够通过的速率。pir必须大于cir。范围0-10000000，单位：kbps。

pbs：指定超出突发尺寸（Peak Burst Size），即瞬间能够通过的峰值流量，即第二个令牌桶的深度（假定该桶为P桶）。范围0-10000000，单位：bytes。

color-blindness：色盲模式使能。enable：色盲模式，disable：色敏模式。

coupling：关联模式使能。enable：关联模式，disable：非关联模式。

使用场景：

### set

命令格式：set priority-mode{ up | down }

使用说明：设置ACL表项的优先级排列模式（递增/递减），默认模式为up，当参数为up时，最初建立的ACL将会以相对低优先级存储，之后建立的ACL优先级递增。当参数为down时，最初建立的ACL将会以相对高优先级存储，之后建立的ACL优先级递减。ACL表项管理区间0-2047,0优先级最低，2047优先级最高。当一个报文同时满足两条甚至多条相同组key类型的ACL匹配时，将会命中优先级较高的一条ACL。注：在执行此命令后，需要先执行uninstall卸载掉所有ACL，然后重新install所需要的ACL！

使用举例：

set priority-mode up		设置ACL优先级排列模式为增序排列。

no：将指定的dscp到queue的映射关系恢复为默认值，默认为queue = dscp/8。

示例：

dscp到queue的映射关系全局只有一个，但cos到queue的映射关系是基于端口的，此命令仅设置映射关系，需结合qos trust及报文类型判断报文进入哪个队列，详细流程参见标签‘qos cos’内的流程图。

格式：

qos map dscp-mutation {RANGES|<dscp_value>} to <dscp_value>

no qos map dscp-mutation {RANGES|<dscp_value>}

参数说明：

dscp-mutation {RANGES|<dscp_value>}：指定dscpdscp映射关系中的原dscp值。

to <dscp_value>：指定dscpdscp映射关系中的目的dscp值。

no：将映射关系恢复默认值。默认dscp不发生突变。

示例：

描述：

dscpdscp映射关系全局只有一个，此处仅配置映射关系，实际能否在出端口改变报文的dscp值还需看对应端口是否配置了‘qos dscp-mutation’及是否是三层转发报文。

### qos shaper-template

格式：

qos shaper-template <template_id> cir <cir_value> cbs <cbs_value>

no qos shaper-template <template_id>

参数说明：

shaper-template <template_id>：指定模板号，共支持0-31共32个模板。

cir <cir_value>：设置承诺信息速率(committed information rate)，范围0-10000000，输入值必须为100的倍数，单位为kbps，即输入数值100，代表cir为100kbps。

cbs <cbs_value>：设置承诺突发尺寸，范围0-10000000，单位为byte，输入值必须为4096的整数倍。KD5886交换机支持的最大cbs为508KB，当设置的cbs超过508KB时，取最大值508KB下发到硬件，可用show qos命令查看实际下发到硬件的数值。

no：将指定的shaper模板的cir和cbs恢复默认值。默认的cir和cbs都是0。此时shaper模板被删除，show qos 时’Rate’和‘Burst’列显示为‘None’。

示例：

配置整形模板1的cir为100Mbps，cbs为16K

KD-CLI(Qos)# qos shaper-template 1 cir 100000 cbs 16384

描述：

当指定cir = 0时，cbs会被强制设置为0，当cbs设置为0时，cbs会被强制设置成4096。

### monitor session

格式：

monitor session <session-id> source interface {RANGES|<source-port-id>} {rx|tx|both}

monitor session <session-id> destination interface <first-dest-port-id> [<second-dest-port-id>]

monitor session <session-id> remote_mirror tag {c_tag|s_tag} vid <vlan-id> pcp <vlan-priority> dei <vlan-cfi>

参数说明：

session <session-id>  : 会话ID，支持0-2共3个会话。

source interface {RANGES|<source-port-id>} ：镜像源端口，每个session的镜像源端口可以有多个， 支持x-y/x,y,z/x-y,z/x,y-z/x五种输入方式。注意输入时逗号后不要有空格。

rx ：将源端口接收到的报文镜像到目的端口。

tx ：将从源端口发送出的报文镜像到目的端口。

both ：将源端口接收和发送的报文都镜像到目的端口。

destination interface first-dest-port-id：镜像目的端口1，支持同时镜像到2个目的端口。

second-dest-port-id：镜像目的端口2。

remote_mirror tag c_tag ：镜像后的报文加一层vlan tag，type = 0x8100。

s_tag ：镜像后的报文加一层vlan tag，type = 0x88a8。

vid <vlan-id>：指定vlan tag内的vid，取值范围1—4094。

pcp <vlan-priority>：指定vlan tag内的pri，取值范围0—7。

dei <vlan-cfi>：指定vlan tag内的cfi，取值范围0—1。

示例：

将端口1、3、5、6、7的接收报文镜像到端口10和11。镜像后的报文加一层s-tag，vlan id 234，优先级4，cfi 1。

KD-CLI(Mirror)# monitor session 1 source interface 1,3,5-7 rx

KD-CLI(Mirror)# monitor session 1 destination interface 10 11

KD-CLI(Mirror)# monitor session 1 remote_mirror tag s_tag vid 234 pcp 4 dei 1

描述：

组播报文tx mirror时，session 1和session 2不可用，只能用session 0。

当多个session的镜像源端口有重合时，最终的镜像目的口选择优先级为session 0 > session 1 > session 2。

out-outer-label：外层标签值,20bits,可选配

arp-id：ARP表的ID, 范围<1-1023>

实例：

KD-CLI(MPLS)# lsp-id 3 tunnel in-label 1000 vrf-id 10 out-label 10000 out-outer-label 20000 arp-id 1023

#### LSP Swap配置

格式：lsp-id <1-2047> swap in-label INTEGER out-interface INTEGER out-label INTEGER [out-outer-label INTEGER] arp-id <1-1023>

lsp-id <1-2047> swap in-label INTEGER out-aggregation-group INTEGER out-label INTEGER [out-outer-label INTEGER] arp-id <1-1023>

no lsp-id <1-2047>

show lsp-id <1-2047>

参数说明：

lsp-id: LSP表ID,范围1-2047

in-label :  匹配的MPLS标签值,20bits

out-label：内层标签值（只有一层标签时，配置out-label）,20bits

out-outer-label：外层标签值,20bits,可选配

out-interface / out-aggregation-group:转发端口或者转发的聚合组

arp-id：ARP表的ID, 范围1-1023

实例：

KD-CLI(MPLS)# lsp-id 2047 swap in-label 2211 out-interface 4 out-label 2200 out-outer-label 1100 arp-id 1

static-ipv4 unicast A.B.C.D prefix <0-32> out-interface INTEGER lsp-id <1-2047> [vrf-id <0-127>]
